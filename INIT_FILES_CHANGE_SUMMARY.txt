ISSUE:
  Vivado batch synthesis on Windows failed to locate memory init files:
  - CRITICAL WARNING: [Synth 8-4445] could not open $readmem data file 
    'digilent_nexys4ddr_rom.init'
  - CRITICAL WARNING: [Synth 8-4445] could not open $readmem data file 
    'digilent_nexys4ddr_sram.init'

CAUSE:
  The Verilog RTL uses bare filenames ($readmemh("digilent_nexys4ddr_rom.init"))
  but Vivado's working directory in batch mode was not set to the gateware

EXPLANATION OF CHANGES:

Change 1: Set Working Directory (lines 7-9)
────────────────────────────────────────────
  set gateware_dir [file dirname [info script]]
  cd $gateware_dir

  Purpose: Make Vivado's working directory equal to the gateware folder
  
  How it works:
    [info script]     → Returns absolute path to the TCL script being executed
    [file dirname ...] → Extracts the directory component
    cd $gateware_dir  → Changes Vivado's working directory to that folder
  
  Result: When Verilog tries to load "digilent_nexys4ddr_rom.init", the bare
          filename is now resolvable relative to the current working directory

Change 2: Add Init Files to Project (lines 21-22)
──────────────────────────────────────────────────
  add_files -fileset sim_1 {digilent_nexys4ddr_rom.init digilent_nexys4ddr_sram.init}

  Purpose: Register the init files with the Vivado project
  
  How it works:
    add_files              → Vivado command to add files to project
    -fileset sim_1         → Add to simulation fileset (works for synthesis)
    {file1 file2}          → Tcl list of files to add
  
  Result: Vivado now explicitly knows about these files and includes them
          in the project, making them available during elaboration/synthesis
