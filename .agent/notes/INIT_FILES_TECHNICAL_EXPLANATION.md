# Init Files Discovery Fix - Technical Explanation

## Problem Statement
During Vivado 2025.2 synthesis on Windows, the build failed with:
```
CRITICAL WARNING: [Synth 8-4445] could not open $readmem data file 'digilent_nexys4ddr_rom.init'
CRITICAL WARNING: [Synth 8-4445] could not open $readmem data file 'digilent_nexys4ddr_sram.init'
```

## Root Cause Analysis

### 1. Verilog RTL References
The generated `digilent_nexys4ddr.v` contains:
```verilog
// Line 11063
reg [31:0] rom[0:7136];
initial begin
	$readmemh("digilent_nexys4ddr_rom.init", rom);  ← bare filename
end

// Line 11078
reg [31:0] sram[0:2047];
initial begin
	$readmemh("digilent_nexys4ddr_sram.init", sram); ← bare filename
end
```

### 2. File Location
Both init files **do exist** in the repository:
```
build/gateware/digilent_nexys4ddr_rom.init  (7,138 lines, BIOS compiled code)
build/gateware/digilent_nexys4ddr_sram.init (empty, L2 cache init)
```

### 3. Windows Batch Mode Issue
When Vivado runs in batch mode (`vivado -mode batch -source digilent_nexys4ddr.tcl`):

**Before Fix:**
- Vivado starts in directory: `C:\Final_Project\litex-nexys4ddr\gateware\`
- TCL script sources with absolute paths for Verilog files
- Init files referenced with bare filenames in Verilog
- Vivado's working directory (CWD) ≠ gateware directory
- `$readmemh()` cannot resolve bare filenames → files not found
- Synthesis continues with uninitialized memories (WARNING, no HARD ERROR)

**After Fix:**
- TCL script explicitly sets CWD to gateware directory
- Vivado working directory = directory where init files exist
- `$readmemh()` can now resolve bare filenames relative to CWD
- Init files loaded during elaboration → synthesis succeeds

## Solution Implementation

### Change 1: Set Working Directory (Lines 7-9)
```tcl
# Set working directory to gateware directory so init files are found
set gateware_dir [file dirname [info script]]
cd $gateware_dir
```

**Why this works:**
- `[info script]` returns absolute path of executing TCL file
  - In batch mode: `/C:/Final_Project/litex-nexys4ddr/gateware/digilent_nexys4ddr.tcl`
  - In GUI mode: similar absolute path
- `[file dirname ...]` extracts the directory: `C:/Final_Project/litex-nexys4ddr/gateware`
- `cd $gateware_dir` changes Vivado's working directory to gateware
- All subsequent relative paths (including init files) resolve from this directory

### Change 2: Add Init Files to Project (Lines 21-22)
```tcl
# Add memory init files as project data files so Vivado can find them during synthesis
add_files -fileset sim_1 {digilent_nexys4ddr_rom.init digilent_nexys4ddr_sram.init}
```

**Why this helps:**
- `add_files` registers files with the Vivado project
- Tells Vivado these are data/memory files needed for elaboration
- Project tracks them so they're available during all phases (synth, sim, impl)
- `-fileset sim_1` uses standard simulation fileset (works for synthesis too)
- File list format `{file1 file2}` handles spaces and special characters

## Backward Compatibility

This fix is **100% backward compatible**:
- GUI mode: `cd` in script changes Vivado's CWD within GUI session (harmless)
- Batch mode: `cd` ensures correct CWD (fixes the bug)
- Linux build: TCL never executed (build uses Python SoC generator)
- No changes to design logic, memory architecture, or functional behavior
- `add_files` is idempotent (can run multiple times safely)
