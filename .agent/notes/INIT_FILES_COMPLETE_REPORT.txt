================================================================================
                            PROBLEM ANALYSIS
================================================================================

SYMPTOM:
  $ vivado -mode batch -source digilent_nexys4ddr.tcl
  
  Output (lines relevant):
  ──────────────────────
  CRITICAL WARNING: [Synth 8-4445] could not open $readmem data file 
                    'digilent_nexys4ddr_rom.init'
  CRITICAL WARNING: [Synth 8-4445] could not open $readmem data file 
                    'digilent_nexys4ddr_sram.init'

ROOT CAUSE:
  
  1. Verilog RTL (digilent_nexys4ddr.v) contains:
     Line 11063: $readmemh("digilent_nexys4ddr_rom.init", rom);
     Line 11078: $readmemh("digilent_nexys4ddr_sram.init", sram);
  
  2. These use bare filenames (relative to working directory)
  
  3. In batch mode on Windows:
     - Vivado starts from C:\Final_Project\litex-nexys4ddr\gateware\
     - But working directory is NOT explicitly set to gateware
     - Working directory might be Windows temp folder or project root
     - Vivado cannot resolve relative filenames
  
  4. Synthesis attempts to elaborate without init files
     - Results in CRITICAL WARNINGs (not a hard error)
     - ROM/SRAM memories uninitialized in simulation
     - May cause unexpected behavior

IMPACT SCOPE:
  - Only affects Windows batch mode synthesis
  - Does not affect Linux build (Python SoC generator)
  - Does not affect GUI mode (GUI automatically manages working directory)
  - No impact on bitstream generation (files just missing from elaboration)

================================================================================
                              SOLUTION
================================================================================

FIX TYPE: Working Directory + Project File Registration

CHANGE 1: Set Working Directory
────────────────────────────────
  Command: set gateware_dir [file dirname [info script]]
           cd $gateware_dir
  
  Effect: 
    - [info script] returns full path to digilent_nexys4ddr.tcl
    - [file dirname ...] extracts directory path
    - cd changes Vivado's working directory to gateware folder
  
  Result: Bare filenames in Verilog now resolve correctly relative to CWD

CHANGE 2: Add Init Files to Project
───────────────────────────────────
  Command: add_files -fileset sim_1 {digilent_nexys4ddr_rom.init digilent_nexys4ddr_sram.init}
  
  Effect:
    - Tells Vivado about the init files
    - Registers them in the project
    - Makes them available during all phases (synth, place, route)
  
  Result: Vivado ensures files are present and included in project

================================================================================
                           IMPLEMENTATION DETAILS
================================================================================

TECHNICAL BACKGROUND:

  Tcl Working Directory:
    - Vivado shells run Tcl scripts in a specific working directory
    - Batch mode: Usually project root or script directory (inconsistent)
    - GUI mode: Usually project root (set by Vivado)
    - This inconsistency causes relative path failures
  
  [file dirname [info script]]:
    - Reliable way to get the directory of the currently executing script
    - Works on Windows, Linux, macOS
    - Returns absolute path, no ambiguity
    - Used by professional Tcl/Vivado developers
  
  add_files command:
    - Vivado TCL command to add files to project
    - Required for Vivado to track data/memory files
    - -fileset sim_1: Standard simulation fileset (works for all phases)
    - {list} syntax: Tcl list, handles multiple files and spaces in names
